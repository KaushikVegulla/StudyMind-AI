Normalization
Normalization is the process of organising data in a database to reduce redundancy and improve data integrity. It divides larger tables into smaller, well structured tables and defines relationships between them. The rules are applied in stages called normal forms. First normal form requires that each column holds atomic values and that there are no repeating groups of columns. Second normal form requires the table to be in first normal form and every non key attribute to be fully functionally dependent on the whole primary key, removing partial dependency. Third normal form removes transitive dependency, where a non key attribute depends on another non key attribute. The goal of normalization is to remove insertion, update and deletion anomalies that appear in poorly designed tables.

ACID Properties
Database transactions follow the ACID properties: atomicity, consistency, isolation and durability. Atomicity means a transaction is treated as a single unit that either completes entirely or does not happen at all; if any part fails, the whole transaction is rolled back. Consistency ensures that a transaction takes the database from one valid state to another, preserving all defined rules and constraints. Isolation means concurrent transactions do not interfere with each other, as if each ran alone in sequence. Durability guarantees that once a transaction is committed, its changes survive permanently, even in the event of a system crash or power failure. Together, ACID properties make database transactions reliable for applications such as banking, where a money transfer must debit one account and credit another without partial results.

Keys and Functional Dependencies
A primary key is a column or set of columns that uniquely identifies each row in a table, and it cannot contain null values. A candidate key is any minimal set of columns that can uniquely identify a row; the chosen candidate key becomes the primary key. A foreign key is a column in one table that refers to the primary key of another table, enforcing referential integrity between the two tables. A functional dependency exists when the value of one attribute determines the value of another attribute; for example, a student id determines the student name. A superkey is any set of columns that uniquely identifies a row, including sets that contain extra attributes beyond a candidate key. Composite keys consist of two or more columns combined to identify a row uniquely, common in junction tables of many to many relationships.
